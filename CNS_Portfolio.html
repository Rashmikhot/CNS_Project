VaultShield

An encrypted credential vault that never sees your passwords, paired with a lab that launches four real attacks against itself and proves each defence works.

Try the attack labGitHub repo 






 
What it is

 
A browser-based password vault where all encryption happens on the client. A local Python server acts as a simulated cloud and only ever stores ciphertext.

Client-side encryption

Two-password design

Implementation & Results


    


        

            Secure Credential Encryption
            

                Implemented client-side AES-256-GCM encryption to protect
                stored credentials before they are transmitted to the
                backend. PBKDF2-HMAC-SHA256 is used for passphrase-based
                key derivation with 600,000 iterations.
            

        


        

            Cyber Attack Simulation & Defence
            

                Developed controlled simulations for Man-in-the-Middle,
                Replay, Password Guessing and Ciphertext Tampering attacks.
                Each scenario demonstrates the corresponding security
                mechanisms and defence concepts.
            

        


        

            Backend Security & Data Protection
            

                Integrated a FastAPI backend with SQLite for storing
                encrypted credential data and metadata. Implemented
                session handling, access controls, integrity verification
                and secure credential operations.
            

        


        

            Testing & Verification
            

                Successfully executed 63 automated tests covering
                authentication failures, tampered records, cross-user
                access, stale updates, session handling and recovery
                after application restart. TLS 1.3 was also verified
                through the HTTPS self-test.
            

        


        

            Security Scope & Limitations
            

                VaultShield is designed as a local educational
                demonstration environment. The current demo uses
                localhost HTTP and is not a production security audit.
                Passphrase recovery and complete rollback protection
                against a malicious server are not implemented.
